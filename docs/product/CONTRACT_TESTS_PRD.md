# 解析与导出契约测试集 PRD

## 背景

当前平台已覆盖需求文档解析、AI 需求分析、测试用例生成、评审、导出与部署链路。随着 PDF、Word、Excel、图片 OCR、多模态模型、Mermaid 流程图、Excel 导出等能力增多，回归风险主要集中在“输入/输出契约漂移”：

- 同一份需求材料在不同解析路径下字段不一致。
- AI 半结构化输出被前后端解析成不同用例。
- 需求分析报告中的 Mermaid 流程图可预览，但 PDF 导出缺图或失败。
- 用例导出格式与业务约定列顺序、文件类型不一致。

本需求建设一套可持续扩展的契约测试集，用固定样例验证关键转换链路，降低后续 prompt、解析、导出、依赖升级导致的回归风险。

## 目标

1. 固化核心链路输入输出契约：解析结果、用例字段、流程图、导出文件。
2. 让回归测试能在本地和 CI 中快速运行，不依赖真实外部 AI、COS 或 OCR 服务。
3. 为后续新增文件类型、模型输出样式、导出格式提供统一样例目录和断言规范。
4. 本次先修复并覆盖两个已知问题：
   - 需求分析导出的流程图渲染失败或被跳过。
   - 导出用例时应产出 `.xlsx` 文件。

## 非目标

- 不在本期引入真实 AI 端到端在线回归。
- 不替代 Playwright E2E，只补充稳定、快速、可重复的契约测试。
- 不重构业务页面或改动评审中心工作流。
- 不改变现有导出表头语义，除非为修复 `.xlsx` 文件格式所必需。

## 用户故事

### 测试负责人

作为测试负责人，我希望固定样例的 AI 输出每次都能解析出相同字段，这样我能放心升级 prompt 或解析规则。

### 开发者

作为开发者，我希望修改 Mermaid、导出、解析逻辑后能快速知道是否破坏既有契约，而不必手工跑完整平台。

### 平台管理员

作为平台管理员，我希望导出的用例文件格式稳定为 Excel `.xlsx`，便于直接交付或导入其他测试管理系统。

## 功能范围

### 契约测试样例

样例按能力域组织：

- `fixtures/ai-output`：AI 生成用例的 JSON、Markdown、半结构化文本。
- `fixtures/analysis-report`：需求分析 Markdown，包含 Mermaid 代码块。
- `fixtures/export`：用于导出断言的标准测试用例数据。

### 契约断言

首期覆盖：

- Mermaid 规范化不破坏常见 flowchart 节点语法。
- 需求分析 PDF 导出前能从 Markdown 提取并渲染 Mermaid 图片。
- 无服务端 suiteId 的前端兜底导出也能生成 `.xlsx`。
- `.xlsx` 表头与既有业务列顺序一致。

### 文档

新增 PRD 和技术文档，说明样例目录、断言原则、命令和扩展方式。

## 验收标准

- 前端单元测试包含 Mermaid 规范化与 `.xlsx` 兜底导出断言。
- 契约测试样例文件可被测试直接读取。
- 执行 `pnpm -C frontend test:unit` 时契约测试通过。
- 执行 `pnpm -C frontend build` 时类型检查通过。
- 后端现有测试不因导出改动回归。

## 风险与约束

- 浏览器环境下生成 `.xlsx` 需复用现有前端依赖，例如 `jszip`，不新增高风险导出库。
- Mermaid 真实渲染依赖 DOM 与动态 import，单元测试优先覆盖可确定的规范化和提取逻辑；端到端渲染仍由 E2E 或人工验证补充。
- 为避免外部服务不稳定，契约测试不得调用真实 AI、COS、OCR、邮件服务。
