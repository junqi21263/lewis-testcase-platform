# 项目使用手册

适用对象：项目管理员、测试负责人、用例评审人员、日常使用者。

适用版本：当前 `develop` / `main` 主线能力，覆盖 AI 需求分析、用例生成、质量检查、Prompt 评测、评审中心与发布配套流程。

## 2. 角色视角下的主流程

### 管理员

1. 登录系统。
2. 进入 `设置中心` 配置 AI 模型、视觉模型、默认策略。
3. 进入 `模板管理` 维护 Prompt 模板并执行评测。
4. 进入 `团队管理` 管理成员、邀请码与角色。

### 分析/测试负责人

1. 进入 `AI 需求分析` 上传需求文档、PDF、图片或直接粘贴文本。
2. 确认结构化报告、REQ/TP 提取与流程图渲染结果。
3. 跳转到 `生成用例`，基于分析结果生成测试用例。
4. 检查 AI 质量报告，必要时二次生成或修复。
5. 进入 `评审中心` 做人工修订、评论和覆盖确认。
6. 导入执行结果，形成需求覆盖闭环。

### 普通使用者

1. 查看 `生成记录` 或 `评审中心` 中已沉淀的结果。
2. 使用导出能力获取 `xlsx`、`json`、`markdown` 等交付件。

## 3. 登录与账号

### 登录

- 入口：`/login`
- 当前以用户名 + 密码登录为主。
- 若管理员启用了邀请注册，可从登录页进入注册入口。

### 注册

- 需邀请码时，按邀请码链路注册。
- 邮箱用于验证与通知，用户名用于登录。

### 常见问题

- 登录后又跳回登录页：通常是模型配置没问题，但鉴权信息未持久化；刷新一次页面再试。
- 邮件收不到：检查 `MAIL_*` 环境变量以及后端邮件服务配置。

## 4. AI 需求分析

入口：`/ai-analysis`

### 支持的输入方式

- 上传文档
- 上传 PDF
- 上传图片
- 文本输入
- 从已有需求分析结果继续

### 标准操作

1. 选择输入来源。
2. 上传文件或填写需求描述。
3. 选择或调整分析 Prompt。
4. 点击开始分析。
5. 观察右侧实时终端与状态日志。
6. 检查输出的结构化报告、REQ/TP、Mermaid 流程图、评分卡和待确认问题。
7. 需要继续生成用例时，直接跳转到 `生成用例`。

### 结果怎么看

- `REQ-ID`：需求点编号，用于后续覆盖追踪。
- `TP-ID`：测试路径编号，用于流程、分支、异常路径映射。
- Mermaid：用于展示主流程、分支、异常路径。
- 评分卡：用于判断需求输入是否完整、可执行、可转测试。
- 待确认问题：提示需求模糊、冲突或缺信息的位置。

### 失败排查

- 流程图渲染失败：先看报告文本是否包含非法 Mermaid 语法，再看浏览器控制台和后端分析日志。
- PDF 解析慢：通常是多模态/分页 OCR 路径触发，检查文件页数、图片密度和模型状态。
- 任务中断：查看记录页或运行态恢复能力是否保留了 stream 快照。

## 5. 用例生成

入口：`/generate`

### 典型流程

1. 选择输入来源：手动输入、上传文件、从需求分析导入。
2. 选择模板和模型。
3. 配置执行策略。
4. 点击生成。
5. 查看右侧生成结果和分页列表。
6. 导出或进入评审中心。

### 当前导出格式

- Excel：`.xlsx`
- Markdown：`.md`
- JSON：`.json`

### 结构化约束

平台现在优先推动 AI 输出遵守严格 schema。即便模型本身不支持严格 `json_schema`，平台也会：

1. 先尝试严格结构化输出。
2. 不支持时自动回退兼容模式。
3. 本地做 schema 校验与自动修复。
4. 记录评测中的兼容性与风险提示。

## 6. AI 质量检查

质量检查主要出现在生成结果、记录详情和 Prompt 评测工作台中。

### 关注维度

- 需求点覆盖率
- 重复用例检测
- 空泛用例检测
- 不可执行用例检测
- 风险等级分布
- 优先级分布
- AI 改进建议

### 怎么用

1. 生成完成后先看质量报告，不要直接导出交付。
2. 如果覆盖率低，回到模板或需求输入补充上下文。
3. 如果重复率高，优先优化模板约束，减少“同义重复”。
4. 如果不可执行用例多，检查步骤/预期结果是否没有落到具体动作和具体提示。

## 7. Prompt 模板与评测工作台

入口：`/templates`

### 模板管理

- 新建模板
- 编辑模板
- 模板版本号管理
- 复制全文
- 直接用于生成

### 评测工作台

点击模板卡片上的 `评测` 后，会进入 Prompt 评测工作台。

当前评测由后端执行，前端主要负责：

- 展示任务创建状态
- 展示各阶段进度
- 展示样例结果
- 展示格式体检
- 展示 AI 优化建议

### 看哪些结果

- 样例数
- 解析成功率
- 平均质量分
- 平均覆盖率
- 兼容性告警
- JSON 截断 / Token 风险
- 平台补修依赖程度

### 评测慢的原因

常见原因有三类：

1. 模板本身要求生成过多条用例，输出体积过大。
2. 模型不支持严格 `json_schema`，平台要做兼容修复。
3. 评测同时跑原模板和优化模板，还要做指标对比。

建议：

- 评测时使用 6 到 10 条代表性样例，而不是直接跑正式批量下限。
- 先让模板明确输出纯 JSON、顶层 `cases`、固定枚举，再追求极致覆盖。

## 8. 评审中心

入口：`/reviews/:recordId`

### 可以做什么

- 查看生成版本
- 编辑测试用例
- 增删改用例
- 写评论
- 查看覆盖矩阵
- 导入执行结果
- 回溯 AI 自动补齐和修复原因

### 推荐评审顺序

1. 先看覆盖矩阵，确认关键需求点是否都被覆盖。
2. 再看高优先级用例。
3. 最后处理边界、异常和重复问题。

## 9. 生成记录

入口：`/records`

记录页用于管理所有历史生成结果。

可执行操作包括：

- 筛选
- 查看详情
- 分享
- 导出
- 批量操作
- 跳转评审

如果任务是长任务或流式任务，记录页也会承接部分运行态恢复入口。

## 10. 设置中心

入口：`/settings`

### 重点配置

- 默认模型
- 视觉解析模型
- API Key / Base URL / 模型名
- 长输出预算
- 外观与天气效果
- 邀请注册/邮件相关能力

### 配置建议

- 先配置一个稳定的文本模型用于需求分析和用例生成。
- 再配置一个可处理图片/PDF 的视觉模型。
- 如果某模型不支持严格 schema，不是不能用，但评测和生成时会更多依赖平台修复。

## 12. 常见排查清单

### 1. 页面没更新

- 先确认分支是否推对。
- 再确认 CNB 是否构建成功。
- 再执行对应环境部署脚本。
- 最后强制刷新浏览器。

### 2. Prompt 评测创建成功但结果异常

- 看后端是否返回了有效任务 ID。
- 看当前模型是否支持严格 schema。
- 看是否触发了最大 Token 截断。

### 3. Redis 里看到很多 `queue:*` 和 `stream:*`

这是运行态缓存和轻量队列，不是异常配置。常见包括：

- `queue:file-parse`
- `queue:ai-analysis`
- `stream:*`

分别用于文件解析任务、分析任务和流式输出快照。

### 4. 文件上传/解析失败

- 检查 COS 配置或本地上传目录。
- 检查多模态模型是否可用。
- 检查后端日志中是下载失败、OCR 失败还是模型返回失败。

## 13. 推荐验证路径

每次发版后，至少手工走一遍下面链路：

1. 登录系统。
2. 进入 `AI 需求分析` 上传一个小型 PDF 或文本需求。
3. 确认报告能出、Mermaid 能渲染。
4. 跳转 `生成用例` 并生成结果。
5. 检查质量报告是否可见。
6. 导出 `xlsx`。
7. 进入 `评审中心` 查看版本和覆盖矩阵。
8. 打开 `模板管理` 触发一次 Prompt 评测。

这条链路能覆盖当前最核心的产品能力。
