# 开发路线图

更新时间：2026-06-22

本文替代旧的“环境可信 / 可重复发布”阶段计划，聚焦当前已经进入的产品化与运行稳定阶段。

## 当前阶段

项目已完成从“单次 AI 生成工具”到“需求分析 -> 用例生成 -> 质量检查 -> 评审回写 -> 覆盖追踪”闭环平台的转型。接下来重点不再是堆页面，而是控制复杂度、增强可观测性和补齐真实环境验证。

## 已完成

### 产品闭环

- AI 需求分析
- 用例生成
- AI 输出质量评分与覆盖分析
- 评审中心与版本历史
- 执行结果导入
- 需求覆盖矩阵
- Prompt 模板管理与评测工作台

### 运行与部署

- develop / main 双环境发布脚本
- Redis 运行态缓存、流式快照、轻量队列
- 安全磁盘守护脚本
- CNB 构建 + VPS 部署链路

## 下一阶段（P0）

### 1. 拆分核心大模块

目标：

- 降低 `AiService`、`FilesService`、`AiAnalysisPage`、`GeneratePage` 的复杂度集中
- 让需求分析、生成、修复、流式恢复、文件解析、运行态同步各自边界更清晰

交付：

- 后端编排层与领域服务拆分
- 前端大页面按工作区、结果区、终端区、质量区拆组件

### 2. 真实环境链路验证

目标：

- 把真实 PDF、真实模型、真实 COS、真实 Redis 恢复从“手工验证”变成稳定 smoke

交付：

- 固定 PDF/图片测试夹具
- develop 环境 smoke 命令
- 发布后最小回归脚本

### 3. Prompt 评测稳定化

目标：

- 继续降低大 JSON 截断、schema 降级、评测耗时过长的问题

交付：

- 评测采样策略优化
- 模板格式自检增强
- 更明确的任务阶段与错误分类

## 中期阶段（P1）

### 1. 长任务可观测性

- 运行态任务面板
- 队列长度、失败次数、重试、心跳和耗时展示
- Redis 降级提示和恢复入口

### 2. 外部系统集成

- Jira / TAPD / 飞书需求与用例映射
- 执行结果回写外部协作平台
- 覆盖矩阵导出与同步

### 3. 安全与审计

- 月度依赖审计
- 模型密钥轮换与最近使用审计
- 更细的管理员操作留痕

## 长期阶段（P2）

### 1. Agent 自动执行增强

- 从“建议与闭环修复”走向“自动执行与结果回写”
- 接入更稳定的自动化执行反馈模型

### 2. 成本与配额治理

- 多模型成本统计
- 模板与任务级预算策略
- 大任务分批与配额控制

### 3. 团队协作能力

- 团队级模板库
- 评审流程规则化
- 更完整的角色与审批策略

## 不再建议继续保留的旧思路

- 继续把大逻辑堆到单个 service 或 page
- 把生成产物、临时截图、二进制手册直接提交仓库
- 同一份 agent/workflow 文档在多个目录维护副本

## 维护规则

- 每次完成 P1 以上能力，必须同步更新 `README.md`、`CHANGELOG.md` 和本文件。
- 已完成事项写入“已完成”，不要继续堆在待办区。
- 被明确废弃的方案应从路线图删除，而不是长期保留为噪声。
